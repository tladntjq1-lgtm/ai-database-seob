## 3-4. JOIN 상세 결과 관찰

```text
학생 A가 나타난 행 수:2행 (question_id 101, 102)
학생 B가 나타난 행 수:1행 (question_id 103)
학생 C가 나타난 행 수:0행 (결과에 아예 나타나지 않음)
```

다음 질문에 답합니다.

### Q1. 학생 C가 왜 결과에서 사라졌나요?

```text
INNER JOIN은 두 테이블에서 조건이 서로 매칭되는 행만 남기는데, 학생 C는 ch01_questions에
student_id가 3인 행이 하나도 없어서(질문을 한 번도 안 써서) 매칭될 행이 없다. 그래서
INNER JOIN 결과에서 아예 빠지게 되었다.
```

### Q2. 학생 A가 왜 여러 행으로 나타났나요?

```text
학생 A는 질문을 두 번(101, 102) 작성했기 때문에, student_id 기준으로 조인할 때마다
각 질문과 한 번씩 짝지어져서 총 2개의 행으로 나타났다.
```

### Q3. 위 `COUNT(*)`가 실제로 세고 있었던 것은 무엇인가요?

```text
학생 수를 센 게 아니라, INNER JOIN으로 매칭된 (학생, 질문) 짝의 행 개수를 센 것이다.
학생 A가 2행, 학생 B가 1행을 만들어 합쳐서 3이 나온 것이지, 실제로 몇 명의 학생이
있는지를 세는 쿼리가 아니었다.
```

### Q4. 결과 숫자가 우연히 실제 학생 수와 같아도 바로 믿으면 안 되는 이유는 무엇인가요?

```text
이번 데이터에서는 매칭된 행 개수(3)와 실제 학생 수(3)가 우연히 같았을 뿐이다. 두 값은
원래 의미가 다르기 때문에, 데이터가 조금만 바뀌어도(예: 학생이 질문을 하나 더 쓰면)
매칭 행 개수는 바뀌지만 실제 학생 수는 그대로일 수 있다. 즉 숫자가 맞아떨어졌다고 해서
쿼리가 업무 질문에 맞게 작성됐다는 보장은 없다.
```

## 3-5. 질문 한 건을 추가한 뒤 다시 실행

추가한 데이터:

```text

INSERT INTO ch01_questions (question_id, student_id, question_text)
VALUES (104, 1, '네 번째 질문')
```

다시 실행한 결과

```text
AI SQL 결과:4
실제 학생 수:3
```

### 결과 해석

```text
데이터가 바뀐 뒤 무엇이 달라졌는지:학생이 아니라 질문 데이터를 한 건 추가했을 뿐인데, INNER JOIN 결과의 행 수가 3에서 4로 늘어났다.

실제 학생 수는 왜 그대로인지:가한 것은 학생이 아니라 질문이므로 ch01_students 테이블에는 변화가 없고, 실제 학생 수는 여전히 3명이다.

이 실험을 통해 알게 된 점:INNER JOIN을 이용한 COUNT(*)는 "학생 수"가 아니라 "매칭된 행 수"를 센다는 것을 직접 확인했다. 데이터가 조금만 바뀌어도 이 값은 실제 학생 수와 상관없이 달라질 수 있으므로, SQL이 오류 없이 실행되고 그럴듯한 숫자가 나오더라도 그것이 곧 업무 질문에 맞는 정답이라는 뜻은 아니라는 것을 배웠다.
```

# 8. 기준 데이터·파생 데이터·AI 생성 결과 구분

내 서비스에 맞게 작성합니다.

| 구분 | 내 서비스의 예 | 판단 이유 |
| --- | --- | --- |
| 기준 데이터 | 지출내역 | 내가 직접 입력한 원본 기록이며, 다른 모든 계산과 분석의 출발점이 되기 때문 |
| 파생 데이터 | 월별지출, 연별지출 | 지출내역을 모아서 집계해 만든 것이라, 원본(지출내역) 없이는 만들어질 수 없기 때문 |
| AI 생성 결과 | "어떤 항목에서 가장 많이 지출하는가" 분석 | 원본 데이터와 내가 준 질문(지시)에 따라 AI가 해석해서 만들어낸 결과이기 때문 |

### 기준 데이터가 변경되면 파생 데이터는 어떻게 해야 하나요?

​```text
자동으로 바뀌는 것이 아니라, 기준 데이터(지출내역)가 바뀌면 파생 데이터(월별지출,
연별지출)를 다시 집계(재계산)해줘야 정확한 값이 된다. 다시 계산하지 않으면
파생 데이터는 예전 값 그대로 남아 실제와 어긋나게 된다.
​```

### AI 결과만 있고 원본 데이터가 없다면 결과를 충분히 검증할 수 있나요?

​```text
검증할 수 없다. 원본 지출내역이 없으면 "어떤 항목에서 가장 많이 지출했는가" 같은
AI의 분석 결과가 실제로 맞는지 다시 계산해서 확인할 방법이 없기 때문에,
그 결과를 그대로 믿을 수밖에 없는 상태가 된다.
​```

## 이번 Chapter에서 새롭게 알게 된 점 3가지

​```text
